# DSH 线上打开缓慢排查

范围：2026-10-24 23:30–23:35（北京时间），线上 Server/Web v0.1.40。用户反馈打开 DSH 长时间加载。本次没有重启 Agent、终端或替换线上镜像。

## 已观察到的事实

- 排查开始时 Agent 在线，本机 3080 没有监听，也没有运行的 DSH。未授权访问转发站点返回 401，约 1.8 秒；这只能证明站点可达，不能证明 DSH 上游可用。
- 没有发现与本次反馈时间对应的 DSH 启动失败日志。较早的端口冲突记录不能据此认定为这一次的原因。
- 在确认没有运行实例后，经现有启动接口启动 DSH，返回 200。随后一次性票据交换返回 303，页面及 11 个资源均成功，输入区域约 3.2 秒可用，未观察到请求失败或 JavaScript 运行错误；WebSocket 使用 `/api/remote.mux`。
- 再通过线上设备页实际点击“启动并打开 Web”，启动接口耗时约 2.7 秒，输入区域从点击开始约 6.0 秒可用。明确观察到旧入口先创建 `about:blank` 标签页，接口返回前没有等待解释。
- 测试没有发送聊天消息或调用模型。临时票据和短时登录凭据已移除；保留用户 DSH 继续运行。

## 结论与边界

目前可正常打开，**持续加载未复现，历史失败根因未确认**。尚无用户出问题时的浏览器请求或错误证据；本机/独立浏览器成功不能证明用户手机当时的网络、浏览器缓存、授权或页面初始化均正常。

已证实的体验缺陷是空白等待。v0.1.41 本地实现独立等待页、只读状态核对、明确失败原因和重新连接入口，并避免重复点击、旧响应跳转及误重启；这些代码尚未部署，线上表现仍是旧版。不能将该体验修复等同于本次长时间加载根因已解决。

若再次发生，先区分停在 CodeGate 等待页、空白新标签页还是 DSH 内部加载；按启动接口、票据交换、主文档、静态资源和 WebSocket 分段检查。只记录安全的状态码、耗时和错误类型，不把一次性票据、Cookie、Authorization 或完整敏感 URL 写入报告。

# CodeGate 后续体验优化版本计划

日期：2026-10-24。代码基线：v0.1.40。v0.1.41、v0.1.42 已按后续授权完成本地实现并合并到 v0.1.42 发布范围，验收见 [v0.1.41 记录](RELEASE-v0.1.41.md)和 [v0.1.42 记录](RELEASE-v0.1.42.md)；实际部署以发布记录为准，真机验收仍待完成。其余版本仍为规划；实际发布前检查版本号是否被其他修复占用。

目标：让手机和桌面用户都能可靠地打开工作、看清状态、处理异常、核对成果。沿用现有配色与组件，通过入口、层级和恢复流程改善体验。

## 已有能力与本轮边界

- 复用现有 sessionStorage 草稿、项目工作摘要、会话恢复、后台任务取消和在线进程退出通知；不重新包装成全新功能。
- v0.1.40 已补齐已结束会话的恢复与切换；真实 Codex 隔离恢复与浏览器检查不等于其他 CLI、真实手机或全部线上模型链路通过。
- DSH Web 是独立上游页面。CodeGate 页面适配不会覆盖它；本机安装版本为 `0.2.0-rc.2`，上游最新源码不能作为该版本能力证据。
- 已确认：DSH 转发授权当前固定一小时到期，过期返回文字错误；启动失败原因归并，缺少端口冲突的明确恢复入口。窄屏侧栏已有基础折叠，软键盘、触摸及安全区仍待实机验收。
- 2026-10-24 现场：用户手工启动的旧 DSH 占用 3080，CodeGate 启动失败。停止此类实例必须确认任务归属及用户授权，不能按进程名批量结束。
- 本次处置已获用户确认该实例无任务：仅停止核验过的旧 DSH 进程组，经 CodeGate 启动返回 200；独立浏览器通过一次性票据加载真实聊天首页，390px 无页面横向溢出，工作区选择及输入框可见，未发送模型请求。Agent 原进程未重启。现场确认工作区入口显示内部文字 `createMode`，作为 v0.1.42 的文案回归项；软键盘及设置等完整手机流程仍未验收。
- 初始授权为规划；故障处置另记实际结果。后续“开始吧”授权启动 v0.1.41 开发，下列版本不因文档写成而标记交付，不自动提交、推送或部署。

## v0.1.41：DSH 打开与恢复

入口仍在设备页 DSH 区域，使用“打开 DSH”“重新连接”和“停止 DSH Web”等目标文字。配置完成、启动成功、浏览器已加载、上游连接正常分别表达；不要把“新标签页已创建”当作打开成功。

范围：

1. 新标签页显示等待页与返回 CodeGate 入口；区分等待设备、启动 DSH、建立转发、超时和失败。没有阶段回执时只显示可证明的状态。
2. 启动前检查端口；区分 CodeGate 自己管理的实例与外部占用。复用已确认归属且健康的实例；不自动接管、认证或停止外部 DSH。冲突显示可执行说明，不能泄露进程命令行中的凭据。
3. 过期页面提供“返回 CodeGate 重新连接”。经当前账号再次授权后换取一次性票据；不以放宽 Cookie/Origin 校验解决，不静默无限续期。
4. 设备断线、上游退出、Server 重启失去转发状态分别提供恢复路径。重新连接优先复用既有实例；若必须重启，说明对运行任务的影响并等待明确选择。
5. 启动结果不明时先核对再重试；重复点击、超时后迟到回包及跨设备切换不能重复启动或把用户带回旧设备。

设计心理学：说明当前阶段、失败原因和下一步，保留用户控制权；禁止把“转发已配置”映射成“服务正在运行”。

验收：端口空闲/已有受管实例/外部占用、票据过期或重放、授权一小时到期、设备离线、上游退出、弹窗被拦、重复点击、刷新和旧响应。使用可控时钟验证过期；跨账号/设备访问拒绝；无凭据进入日志。真实安装版本完成启动—浏览器加载—重连；测试不得结束用户 Agent 或相邻任务。

## v0.1.42：DSH 手机使用

先用独立 DSH_HOME、固定包版本和虚构测试数据完成布局基线，不操作用户对话，也不发起付费模型调用。

实施方案先做一个兼容性验证：优先已验证的上游移动支持或受支持的本地 UI 插件。若必须维护适配层，固定 DSH 版本、记录选择器/入口契约，并提供禁用与回退；不能直接修改全局 npm 编译文件或随上游升级静默失效。CodeGate 自有启动/错误页先独立改善，不等待上游布局方案。

范围：

- 手机默认突出对话和输入；会话列表、文件和预览按需打开为抽屉或全屏面板，提供文字关闭入口及返回焦点。
- 键盘弹出后输入框、发送/停止按钮可见；正确使用动态视口和设备安全区，横竖屏切换不丢草稿。
- 主操作触摸区域至少 44×44 CSS px，输入字号避免手机自动缩放；长模型名、路径、代码和错误信息不撑破主页面，代码区可单独滚动。
- 设置及模型选择适合窄屏，保留项目/模型/权限的可理解摘要，高级设置逐步展开。
- 修复工作区入口暴露 `createMode` 等内部标识，空工作区、已有工作区及加载失败使用明确目标文案；固定版本验证，不能由另一个上游版本的截图推断修复。

设计心理学：降低主屏密度，操作位置稳定，焦点和返回路径清楚；不能通过隐藏错误、停止入口或费用策略换取简洁。

验收矩阵：320/360/390/430px、桌面、横屏、深浅色、200% 缩放、键盘与读屏；另以真实 Android Chrome / iPhone Safari 验证软键盘、触摸、刘海安全区和系统返回。覆盖聊天、切换会话、模型设置、文件/预览、长文本、加载失败与重连。浏览器模拟通过与实机通过分别记录；没有实机证据不能宣称手机已全面适配。

## v0.1.43：统一待处理入口

在现有项目/设备导航提供轻量“待处理”入口和真实数量，不再向首页叠加多个常驻面板。先汇总现有后台续跑与工作流中可证明的失败、需要确认和停止未确认状态；等待权限仅在 CLI 已有可靠结构化事件时纳入，不从终端文本猜测。

范围：

- 每项显示所属设备/项目、来源类型、当前原因及“查看并处理”；保留原任务作为状态和操作的唯一来源。
- 支持按设备/项目/状态筛选和有界分页；部分设备离线或读取失败时显示结果不完整，不能清空成“全部处理完毕”。
- “已读/收起”和“取消/停止执行”明确分开；收起不删原生历史、不取消任务。已读/收起若跨端同步，需独立持久化并按用户授权。
- 点开原任务后支持现有合法操作；汇总页不因重复事件自动重派发。页面关闭后的 Web Push 不纳入本版，复用已有在线退出通知并保持其语义。

设计心理学：把用户要处理的事集中呈现，减少记忆负担，同时维持会话、续跑、工作流的概念区别。

验收：跨账号隔离、同一来源去重、状态更新与取消竞态、分页变化、部分失败、离线缓存、刷新/重连、已读跨端一致性；旧 Agent 缺失能力明确提示；320px 和键盘可完成处理路径。

## v0.1.44：继续工作与交付回访

复用当前标签页草稿和项目摘要，补齐阅读位置与成果映射。“继续工作”优先回到原会话、任务与面板；恢复终端连接、恢复原生对话和重新执行任务是三个不同动作。

范围：

- 草稿继续按账号、设备/会话、目录隔离；恢复滚动位置与展开状态。已有 sessionStorage 草稿不改成静默上传，敏感文本不进入 URL。
- 跨设备先同步经过授权的工作位置引用；不自动同步终端输入或文件草稿。跨端文本草稿另作明确的隐私与冲突方案后再开放。
- 为有结构化来源的工作流增加交付卡：对应执行尝试、工作区/分支、基准和结果提交、改动、检查结果与证据时间，以及待人工验收项；普通终端只显示已有事实与核对入口。
- 检查必须关联实际提交或内容快照。新改动到来后，旧检查标为过期；证据缺失/读取失败写明，不用模型声称完成或进程退出推断通过。

设计心理学：降低回访成本，让执行结果可核对；用户验收独立于自动检查，不自动提交代码、推送或标记用户接受。

验收：账号退出/切换、存储不可用、来源删除/离线、两端位置冲突、刷新、长列表滚动；相邻执行尝试不串证据，HEAD 改变后旧检查失效，失败保留草稿；手机完成查看改动—查看检查—返回原对话的路径。

## v0.1.45 及后续：按能力推进 CLI 调度

以 [CLI 调度路线图](CLI-ORCHESTRATION-ROADMAP.md) 为唯一技术契约。本版只承诺阶段 A：统一能力/事件/配置快照并迁移现有 Codex/OpenCode，复用现有“项目 → 新建任务 → 主 Agent 自主调度”。不把安装了 CLI 解释成可担任主脑。

随后按该路线图推进 Claude 工作 Agent、Claude 主脑、DSH ACP 和通用接入，分别在通过准入后再分配发布版本。DSH Web 手机适配不等于 DSH 已可参与主脑调度。

共同门槛：费用策略不被绕过、免费模型不静默转付费；授权工作区和工具边界保持；取消有真实确认，身份不明不重放；断线/崩溃和旧 Agent 有明确恢复；真实模型的编辑/验证/取消与界面证据独立验收。

## 开发与发布标准

1. 每版先为行为变化建立会失败的针对性回归，再实现正常、失败/等待、恢复路径；异步操作必须覆盖取消及旧响应。
2. 按变更选择 Go/Web 测试、类型检查、构建和真实浏览器/CLI 验证；文档变更不运行无关构建。模拟、实机、真实模型与线上验收分别记录。
3. 保留现有项目视觉语言；桌面和手机同一任务顺序，高级选项逐步展示，关键原因及恢复入口不能只靠图标或悬浮提示。
4. 涉及协议使用 capability 门控；涉及持久化先评估迁移、索引、旧版读取及数据库回滚。部署必须保留备份和回滚镜像，不强制重启有运行会话的 Agent。
5. 完成后按当次授权提交和发布，更新对应版本记录；已上线、已下载、等待空闲、已实际运行新版分别报告。

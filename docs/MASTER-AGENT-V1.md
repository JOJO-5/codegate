# 主 Agent 自主调度：本机第一版

用户选择一个主 Agent 的 CLI / 模型和项目，填写目标及验收条件。任务拆分、工作模型选择、检查、验证和返工由主 Agent 决定。界面不要求用户手动搭建规划、实现、评审的流水线。

## 使用

1. Server 与目标机器的 Agent 均更新到支持 `workflow_v1` 的版本。在目标机器安装并登录 Codex 或 OpenCode V2，在 CodeGate 授权相应 CLI。凭据始终留在本机。
2. 项目需要有 Git 初始提交。进入项目 → 新建任务 → 执行方式选“主 Agent 自主调度”。选择主 Agent，描述目标和如何验收。
3. 默认工作模型仅使用本机目录中当前输入、输出及缓存价格全部明确为零的配置。主 Agent 自身的费用取决于所选 CLI / 模型；选择 Codex 不表示免费。高级选项可以调整工作模型策略、决策次数及运行时间。
4. 执行从当前提交建立独立 worktree，原目录未提交改动不带入。可关闭网页；设备需保持开机。设备页展示进度、原生对话身份、步骤、工作区、分支和实际 diff。
5. 点击“取消调度”后，尚未派发的任务直接取消；已派发的任务等待本机确认停止。已产生代码保留。完成仅显示“已交付 · 待你验收”，由用户核对后决定如何合入。

后续扩展见[本机 CLI 统一调度调研与实施规划](CLI-ORCHESTRATION-ROADMAP.md)：Claude Code、DSH ACP 和其他 CLI 的支持仍处于规划阶段，不能把本机已安装工具列表当作调度支持列表。

## 已实现的调度循环

主 Agent 保留一个原生对话，每轮返回一个结构化操作：`delegate`、`inspect`、`check`、`finish`、`need_help`。它可自由安排同一工作区中的串行工作任务、评审或返工；每个工作任务使用新的原生对话。

`check` 只接受本机固定入口：`git_diff_check`、`node_test`、`go_test`、`npm_test`、`npm_build`。测试和构建在工作区根目录执行，单次最多两分钟。依赖需事先具备，当前没有自动安装依赖或任意 Shell 验证入口。OpenCode 工作会话仅使用文件工具，Shell 验证交给主 Agent 的 `check`；本机权限请求或无法核对的执行结果会停止派发。Codex 使用独立 `exec --json` 进程及其原生沙箱，取消不停止用户共享的 Codex 守护进程。OpenCode 复用本机 V2 常驻服务，只控制本工作流自己的会话和输入。

交付必须至少有一个成功工作任务，最新产物通过 `git_diff_check`，并且所有已请求的验证都对最新文件成功。文件再次变化会使旧验证失效。工作分支提交意外改变或 diff 超过预览上限（6000 字符 / Git 输出上限）时，保留产物并请求人工核对，不伪造完整验收。

浏览器的 nonce、Server SQLite 记录、本机执行回执和递增版本共同防止重复提交和旧状态覆盖。派发前先持久化状态，重连时只检查已派发任务；Agent 重启后未结束的回执进入“需要你核对”，不自动重放模型请求。主 Agent 的格式错误只做受决策次数限制的指令纠正，不能导致工作任务重放。

## 当前边界

- 一台机器同时执行一个调度，其余等待空闲。多设备之间的产物传递、并行工作区整合、额度自动换路及跨机续跑属于后续版本。
- 默认最多 12 次主 Agent 决策、30 分钟；最大可配置 32 次、180 分钟。达到限制保留产物，需要用户核对。没有自动推送、合并或发布步骤。
- 原生 CLI 保留其自身的权限与配置。Git worktree 是项目隔离方式，不是宿主机安全沙箱；不要把不可信项目代码当作受限容器运行。受信任的本机工具和测试脚本仍以当前用户执行。
- 自动发现已授权 Codex 配置和 OpenCode V2 免费工具模型。其他明确的模型可在 Agent `workflow_profiles` 里引用已授权 `command_id`，设置 `label`、`model`、`provider`；不能通过网页传可执行文件或供应商地址。免费配置每次派发前重新检查报价，失败不静默转付费。
- 旧 Agent 不会收到无法识别的调度指令。目录读取要求设备在线；离线时可读取、取消已保存的排队记录。

## 设计心理学落实

入口以“交给主 Agent 调度”表达用户目标；主界面只选择主 Agent 和目标，运行上限逐步展示。执行前说明设备、目录、工作区和费用策略；执行后显示真实阶段、验证证据、取消确认及人工验收边界。失败保留草稿和最近已知状态，提交不明沿用原标识核对。开发准则固化于根目录 [AGENTS.md](../AGENTS.md)。

## 验证入口

`go test ./internal/agent ./internal/server ./internal/storage ./internal/protocol` 和 `npm --prefix web run test:ux` 覆盖账户归属、持久化、幂等、取消竞态、格式纠正、费用策略和交付门控。`npm --prefix web run build` 执行 Vue 类型检查与生产构建。

真实免费模型测试必须显式设置 `CODEGATE_OPENCODE_V2_SMOKE` 为本机 OpenCode V2 可执行文件，并设置 `CODEGATE_WORKFLOW_FREE_SMOKE=1`，运行 `TestWorkflowFreeModelCodesAndValidatesInWorktree`。`CODEGATE_OPENCODE_V2_FREE_MODEL` 可明确选择目录中确认免费的 profile；不设置时使用 `opencode/mimo-v2.6-flash-free`，没有付费兜底。普通 CI 跳过托管模型。该测试在临时 Git 项目用免费主模型指挥免费工作模型创建实际代码和 Node 测试，检查实际验证、原目录隔离及原生会话费用；只清理自己的原生会话和临时位置。

2026-10-18 验收状态：结构化调度、隔离、幂等、取消和交付门控的自动化检查已通过；此前真实免费工作模型生成过代码与测试，但完整主 Agent 交付链尚未通过验收。当天 MiMo 和 Big Pickle 的独立原生调用均返回 `provider.auth`，因此真实免费模型完整链路仍未验证通过；不能把模拟检查或构建通过写成真实模型交付成功。

同日后续诊断将本机错误进一步定位为 HTTP 401、凭据过期：独立 Big Pickle 测试的安全诊断输出为 `status=401`，已知错误标记包含 `authentication / api key / expired`。没有输出原始错误正文或凭据。需在本机 OpenCode 使用 `/connect` 重新连接后再跑完整实测，不能据此认定为免费资格 403 或调度器网络故障。认证过期、认证拒绝或明确的免费资格拒绝会暂停派发并保留原生会话；工作模型报告这类阻塞时，不再要求主模型继续决策或反复尝试。

2026-10-18 后续验收：通过本机 OpenCode 原生凭据接口更新认证后，401 阻塞解除。`TestOpenCodeV2FreeModelExecution` 使用当前报价确认免费的 `opencode/big-pickle`，实际回复、运行中取消、相邻会话隔离与两个会话费用为零均通过（7.18秒）。随后 `TestWorkflowFreeModelCodesAndValidatesInWorktree` 使用同一免费模型分别担任主脑和工作模型，4 次决策完成派发、代码生成、Node 测试、差异检查及交付（98.55秒）；原目录保持不变，原生测试会话费用全部为零。测试自己的原生会话和临时目录已清理，用户会话未重启。此结果验证本机免费模型的完整串行链路，不代表所有模型、多机器或线上界面均已验收；当前工作区改动尚未发布。

OpenCode V2 的工具动作名与 V1 有变化，权限适配依据 [V2 官方权限文档](https://opencode.ai/v2/docs/permissions)。不要用无差别的全局 deny 代替只收紧本工作流工具权限，否则会影响原生认证。

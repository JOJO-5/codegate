# 预约与续跑：可观察、可停止、可整理

2026-10-18。本轮为当前工作区的代码审查与交互方案；没有修改该功能的产品代码，没有操作线上任务。沿用现有 Go Server、SQLite、Agent 和 Vue 架构。

用户目标：安排任务后可以离开；回来时知道它是否启动、正在做什么、为何等待，能停止执行，并能清理不再需要的记录。

## 已确认的问题

| 优先级 | 证据 | 用户感受与设计原因 |
| --- | --- | --- |
| P1 | `web/src/components/ContinuationPanel.vue:22–38`：隐藏 ID 放在标签页草稿里；页面也说明退出账号时清除。`web/src/lib/api.ts:493–495` 只有列表、创建、取消，没有删除接口。 | “删不掉”是能力缺失。临时收起不能满足长期整理的目标，操作结果不符合预期。 |

这里主要审查按时间和到时查额度的后台任务。撞墙自动继续使用原生对话控制，执行入口不同；两类可以共享任务列表，但不能假装它们都有同一种交互终端。

## 交互方案

入口仍保留在设备和会话内，沿用当前视觉风格，名称统一为“预约与续跑”。默认展示待处理和正在进行的任务；历史单独查看。

```text
预约与续跑                         [刷新]
[进行中 2] [需要处理 1] [历史记录 18]

项目 / 原对话名称                  后台执行中
本机 · 项目目录 · CLI / 已知模型
已运行 03:12 · 最近活动 8 秒前
当前活动：运行工具（不展示凭据或原始敏感参数）
[查看执行] [停止本次执行]

历史记录                         [清理已结束记录]
原对话名称 · 本次执行结束 · 结束时间
[查看结果] [删除记录]
```

“需要处理”不是普通历史：包括派发结果不明、原生身份不一致、环境失败等。默认保持可见，展示具体原因、最后确认时间和恢复入口。未知结果不得显示为已停止。

### 删除与取消各自兑现目标

- 尚未执行：按钮“取消预约”，成功后成为已取消历史。
- 正在执行：按钮“停止本次执行”；请求后显示“正在停止，等待设备确认”。离线时显示等待确认，保留原状态和最近证据。
- 撞墙监测：按钮“关闭自动续跑”，明确是否只关闭监测、是否正在中断它自己提交的回合。不能结束用户原终端中的其他工作。
- 已结束历史：提供真正的“删除记录”和批量“清理已结束记录”。删除持久化到服务端，刷新、重新登录和其他设备看到相同结果；提供撤销窗口或明确确认。
- 删除只整理 CodeGate 任务记录，保留原生对话、项目文件和已生成代码。运行中及停止未确认的任务不能直接删除。
- “需要处理”允许确认后从列表移除，但必须说明执行结果仍可能未知；清理历史默认排除这类记录，不能用删除代替停止确认。

实现删除时，服务端保留最小幂等凭据或删除标记，避免删除记录后，相同 nonce 的迟到重试重新创建并执行任务。标记不携带原提示词、结果或凭据；不能仅从列表过滤一条前端记录。

### 查看执行，回答“它现在在做什么”

点击“查看执行”打开可恢复的详情页或面板，展示任务 ID、当前尝试、原生对话绑定、执行设备、目录、已知 CLI/模型、开始时间、运行时长与最近同步时间。无法确定模型时写“模型由原会话配置决定”。

详情分成状态、执行活动、模型回复、最终结果：

- 等待时明确等什么：计划时间、设备上线、原终端结束、额度恢复或人工处理。预计重试时间与保证启动时间区分开。
- 后台进程持续报告有界、结构化活动：已启动、模型回复、工具开始/结束、等待确认、进程退出。工具事件不能只凭模型文字推断，未收到活动就如实显示“暂未收到新活动”。
- 不将原始 stderr、环境变量、凭据及未审查的工具参数上传为日志。能力不足的 CLI 显示可用的真实状态，并说明详细活动不可用。
- 按时间/额度启动的无 PTY 进程提供“只读执行日志”，明确不支持终端输入；原终端自动继续提供“打开原终端”的可用链接。只有真实接入 PTY 的执行才能称为可交互终端。
- 原生对话恢复入口在执行中受占用约束，避免并发恢复同一个会话。执行结束后直接查看历史或恢复原对话。
- 断线保留最后数据并标记“连接中断，以下为最后确认状态”，恢复后先查询同一任务/尝试，不重发提示词。
- 实时更新使用现有 Agent WebSocket 通道，服务端保存最近快照供刷新恢复。快照带尝试 ID 与单调序号，过滤迟到更新；不依靠仅在浏览器存活的输出缓冲。

### 降低列表负担

进行中、需要处理、历史按用户目标分组。历史按结束时间分页，默认折叠；执行中的主信息只保留状态、等待原因/最近活动和操作。高级设置、完整提示词和诊断放入详情。

已结束任务显示结束时间；等待任务显示计划或重试时间；正在执行显示已运行时间和最近活动。进程退出只写“本次执行结束”，不冒充代码已经验收。

## 设计心理学如何落实

- 日常的设计：删除、取消、停止、查看执行都有准确命名和可核对的后果；状态与实际执行绑定，缩小操作和评估的鸿沟。
- 与复杂共处：按进行中、需要处理、历史组织复杂状态；等待有原因，详情渐进展示，用户不用理解内部调度循环。
- 情感化设计：本能层减少列表噪声；行为层提供观察和中止；反思层保留执行证据、原对话与用户验收的边界，建立可预测的控制感。

表单、焦点、状态播报和恢复导航同时参考 [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md)。

## 实施顺序与验收

1. 服务端持久删除/撤销与历史整理；明确取消/停止文案；修正结束任务时间和需要处理分组。
2. Agent 结构化活动、带序号快照和服务端回传；前端只读执行面板、原会话入口及断线恢复。
3. 历史分页、批量清理、移动端与键盘完整流程。

行为改动先写针对性失败测试，再实现；至少覆盖：

- 删除已结束记录后刷新、重新登录仍不出现；撤销可恢复；不删除文件或原生历史；跨账号请求被拒绝。
- 运行中禁止删除；停止请求离线时不能伪报成功；旧列表响应不能复活已删除记录或覆盖取消状态。
- 删除与完成回执并发、同 nonce 重试、批量清理中混入活动任务时不产生重复执行或误清理。
- 预约到时启动后，持续活动在执行详情可见；长时间没有输出、设备离线、启动失败均能辨别。
- 刷新与断线后恢复同一次执行；旧尝试和乱序事件不覆盖新状态；日志有界、无敏感字段。
- 完成、失败与结果不明分别展示；提供原对话恢复路径，不并发启动占用中的对话。
- 键盘可打开详情、操作停止/删除/撤销并恢复焦点；窄屏无横向溢出；状态更新可被读屏感知。

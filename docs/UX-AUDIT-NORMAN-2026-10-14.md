**CodeGate 界面与功能审查：设计心理学三部曲**

审查日期：2026-10-14。代码基线：d04a8f0 / v0.1.31。本轮只审查，未修改产品代码或执行线上业务操作。

当前主要问题集中在继续工作、状态反馈、草稿保护和概念组织。项目入口、原对话恢复、独立工作区、后台续跑和 Git 交付已经具备，但用户需要在不同页面之间自行拼接完整工作流程。

**审查方法与边界**

- 阅读项目、设备、设备详情、终端、文件、Git、独立工作区、登录和设置页面，以及相关组件、状态管理和部分后端实现。
- 用现有 Vue 模板编译器和渲染器复现后台续跑与文件列表的失败场景；执行实际 humanizeError 函数验证错误文案。
- 检查了公网登录页的截图和可访问元素。未登录并操作用户的生产账号，未对登录后全部页面完成桌面/移动端视觉回归。
- 文档区分渲染复现、代码确认和设计建议。界面拥挤程度、真实触摸误触、读屏表现和大列表性能仍需实测。

**使用的三个视角**

| 视角 | 核心要素 | 在 CodeGate 中检查什么 |
| --- | --- | --- |
| 日常的设计 | 意符、自然映射、概念模型、反馈、约束与错误恢复 | 按钮是否兑现它的名称；能否知道操作对象、操作后果和失败后的下一步 |
| 与复杂共处 | 可理解的结构、渐进披露、等待体验、设计者与使用者的协作 | 项目、会话、原生对话、分支工作区是否能被理解；复杂功能是否按用户目标组织 |
| 情感化设计 | 本能层、行为层、反思层 | 初见是否清楚；操作是否流畅、有掌控感；回到产品时是否知道上次做了什么、结果是否可信 |

依据：[日常的设计](https://jnd.org/books/the-design-of-everyday-things-revised-and-expanded-edition/)、[与复杂共处](https://jnd.org/books/living-with-complexity/)、[情感化设计](https://jnd.org/books/emotional-design-why-we-love-or-hate-everyday-things/)。键盘、表单和反馈细节另参照 [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md)。

**应该保留的现有设计**

- 会话关闭有明确的二次确认，并说明关闭网页和结束远端进程的区别。
- 项目入口移除支持撤销，并明确文件和会话保留。
- 会话列表区分实时与缓存快照；原生历史恢复、只读与接管、独立分支工作区也已有能力边界。
- 任务模板只预填，用户确认后发送；后台执行结束不被直接称为任务完成。
- Git 推送信息明确说明远端引用未联网刷新；独立工作区清理有占用、文件改动和未合入提交的约束。
- 全局按钮已有键盘焦点样式、深浅色模式和移动端安全区处理。

**P1：优先解决日常损失与流程断点**

1. **未发送/未保存文字会随页面卸载丢失。代码确认。**

   终端输入保存在组件内的 mobileDraft；切换会话、进入 Git 页面或返回设备时会卸载组件。文件面板中的新建文件内容同样是组件内存状态，关闭文件面板会卸载 FilesView。没有草稿保存或离开保护。

   证据：web/src/views/SessionView.vue:141、web/src/views/SessionView.vue:952、web/src/views/SessionView.vue:1084；web/src/views/FilesView.vue:20、web/src/views/FilesView.vue:184；web/src/App.vue:88。

   建议：按账号、设备、会话保存未发送草稿；切换会话后恢复对应内容。新文件未保存时关闭面板或导航需允许保留草稿，明确丢弃才清除。刷新保留与退出账号时清除的规则也应明确。

   心理学对应：为错误设计，保护记忆中的工作，建立行为层的可靠感。

   验收：输入长提示词后切换会话、查看 Git、返回原会话，文字仍在且未自动发送；文件内容同样可恢复。

2. **后台续跑首次加载失败时，错误提示被整个面板隐藏。渲染复现。**

   load() 捕获错误，但列表和错误提示共同置于 visibleRows.length 的条件内。无已有记录、无打开的编辑对话框时，失败状态只渲染空注释节点。用户无法区分没有任务与无法读取任务。

   证据：web/src/components/ContinuationPanel.vue:22、web/src/components/ContinuationPanel.vue:26、web/src/components/ContinuationPanel.vue:66。

   建议：保持后台任务入口可见，分别呈现加载中、空列表、读取失败和已有记录；失败时提供重试。成功读取后清除上一轮错误，避免残留失败文案。

   心理学对应：反馈与评估鸿沟；等待必须有可解释的状态。

   验收：首次请求失败时看到失败原因和重试；再次成功后错误消失；真正空列表显示无后台任务。

3. **文件读取失败时会同时显示“目录为空”。渲染复现。**

   空状态只判断 busy 和 entries.length，没有区分读取成功与失败。首次失败时页面会同时显示错误和空目录结论。

   证据：web/src/views/FilesView.vue:62、web/src/views/FilesView.vue:211、web/src/views/FilesView.vue:212。

   建议：只有成功读取且确实没有条目时显示目录为空；错误时保留上次数据，并标明它的目录和刷新时间。

   心理学对应：系统图像必须真实，反馈不能形成错误的概念模型。

   验收：断网或设备离线时不声称目录为空；重试成功后再显示真实内容。

4. **“继续工作”在已结束会话上没有恢复出口。代码确认。**

   项目首页的最近会话只显示进程已结束；展开项目会话后也只有存活会话的接回动作。设备详情已有恢复原对话能力，但项目页没有衔接，文案还建议通过新建启动新的对话。

   证据：web/src/views/ProjectsView.vue:97、web/src/views/ProjectsView.vue:112、web/src/views/ProjectsView.vue:118；web/src/views/DeviceDetailView.vue:639、web/src/views/DeviceDetailView.vue:662。

   建议：项目页围绕继续原对话组织动作：存活会话接回；有可恢复历史的已结束会话恢复；没有历史的记录说明原因，并单独提供新建对话。离线时保持入口可理解。

   心理学对应：用户目标与执行路径的自然映射；反思层的工作连续性。

   验收：从项目首页即可恢复已保存的原对话，用户无需知道恢复按钮在设备页。

5. **“独立会话”与文件隔离容易混淆。代码确认 + 设计风险。**

   设备页主按钮叫新建独立会话，但 worktree 默认关闭；任务启动器也默认使用原目录。因此不同会话的进程独立，仍可能修改同一套文件。任务启动器已有直接修改目录的说明，这是可复用的较好表达。

   证据：web/src/views/DeviceDetailView.vue:183、web/src/views/DeviceDetailView.vue:560、web/src/views/DeviceDetailView.vue:608；web/src/components/TaskLaunch.vue:21、web/src/components/TaskLaunch.vue:52。

   建议：统一称新建会话，将工作方式明确为共用原目录 / 独立分支工作区。同一目录有其他会话时提示共享文件关系；独立工作区明确未提交修改不会带入。不要静默更改用户选定的工作方式。

   心理学对应：概念模型与约束；降低错误选择带来的焦虑。

   验收：启动前用户能明确回答是否与其他会话共享文件，以及新会话在哪个目录和分支运行。

**P2：提高掌控感，减少理解成本**

6. **更新等待没有足够的解释和控制。代码确认 + 功能建议。**

   目前主要显示等待设备空闲和泛化说明，缺少具体阻塞项、下一轮版本检查时间和取消手动重启安排的入口。请求接受提示没有随着新版本成功上线而转为完成提示。CheckedAt 每次状态变化都会更新，下载后的空闲轮询也会更新时间；界面“最近检查”容易被理解成最近一次联网检查版本。

   证据：web/src/views/DeviceDetailView.vue:142、web/src/views/DeviceDetailView.vue:170、web/src/views/DeviceDetailView.vue:786；internal/agent/update.go:60、internal/agent/update.go:133。

   建议：显示当前版本、目标版本、包是否已下载，以及真实阻塞原因，例如 1 个运行会话 / 2 个保留输出 / DSH Web。分离版本检查时间与状态更新时间；展示下一次检查时间。手动安排的重启可取消，检测到新版本上线后明确显示升级完成。

   心理学对应：反馈、等待的设计、自动化中的用户控制。

   验收：用户能判断为什么还没升级、现在需要做什么、安排是否仍有效，完成后不再看到待执行提示。

7. **业务错误被 5xx 通用文案覆盖。函数执行复现。**

   device_offline / 503 和 agent_timeout / 504 都被 humanizeError 转成服务端出错了，请稍后重试，丢掉设备离线或 Agent 未响应的具体解决方向。

   证据：web/src/lib/format.ts:156。

   建议：优先按可信业务错误码映射到可执行的下一步；未识别的服务端错误才使用通用文案。保持不存在与无权访问不可区分的原有权限边界。

   心理学对应：错误恢复；避免让用户错误归因。

8. **几个按钮承诺与到达的页面不一致。代码确认。**

   项目页添加项目只导航到设备列表；终端中的新会话调用 goBack() 返回设备详情。用户还要重新找到真正的创建入口。设备与工具 / 独立工作区把多个目的混在一个标签中。

   证据：web/src/views/ProjectsView.vue:86、web/src/views/ProjectsView.vue:127；web/src/views/SessionView.vue:771、web/src/views/SessionView.vue:1042。

   建议：添加项目直接进入选设备、选目录、保存项目的流程；新会话带当前设备和目录打开启动器。导航标签只描述它的实际目的。

   心理学对应：意符和自然映射；减少执行鸿沟。

9. **终端操作分组和快捷路径需要重新组织。代码确认，密度待实测。**

   更多按键里同时放着翻页、复制、字号、查找、重绘和关闭会话。关闭会话不是按键设置，特别是 Windows shell 无法安全 Ctrl+C 时，说明指向的替代动作又藏在此处。

   证据：web/src/views/SessionView.vue:1132、web/src/views/SessionView.vue:1176、web/src/views/SessionView.vue:1188。

   建议：区分输入辅助、查看输出、会话操作。常用发送/粘贴/搜索可直接访问；结束进程放在有明确语义的会话操作菜单中并保留确认。结合手机键盘展开状态检查终端可见面积和返回焦点。

   心理学对应：按活动组织复杂性，而不是按实现上的工具集合组织。

10. **两个模态框只有模态语义，未实现完整键盘行为。代码确认，读屏待实测。**

   后台续跑与恢复对话使用普通 div/section 加 role=dialog、aria-modal；未实现焦点限制、Escape 和关闭后返回原触发按钮。新建项目使用原生 dialog，可作为统一实现的参考。

   证据：web/src/components/ContinuationPanel.vue:47；web/src/components/ConversationRecovery.vue:47；web/src/components/NewProjectDialog.vue:24。

   建议：统一模态组件或使用原生 dialog，管理初始焦点、Tab 范围、Escape、关闭后的焦点恢复；提交中锁定影响请求含义的字段。

   心理学对应：操作约束、行为层的确定性，以及不同输入方式的一致体验。

11. **仓库卡片中的工具选择实际按设备共享。代码确认 + 映射风险。**

   每张仓库卡片看起来有自己的 CLI 选择，但 repoCommands 以 device_id 为键；在一个仓库选择工具会影响同设备其他仓库的显示和启动工具。

   证据：web/src/views/ProjectsView.vue:15、web/src/views/ProjectsView.vue:38、web/src/views/ProjectsView.vue:149。

   建议：若想按仓库选择，使用设备加仓库路径作为键；若想统一设备工具，在设备或列表顶部提供全局选择，并明确作用范围。

   心理学对应：控制与作用对象的自然映射。

12. **工作结果分散，缺少再次回来时的总结。设计建议。**

   原生对话、后台续跑输出、Git 文件改动、未推送提交和退出提醒分别处于不同页面。通知正确地只说明进程退出，但无法单独回答工作完成到哪一步。

   证据：web/src/components/ContinuationPanel.vue:39、web/src/views/GitView.vue:82、web/src/views/SettingsView.vue:134。

   建议：项目视图增加最近工作摘要，将原对话、实际执行结果、改动和交付状态连在一起。对任务完成保持人工确认或明确的可验证来源，区分进程退出、本次执行结束、测试通过、已推送与已验收。

   心理学对应：反思层的可信度、工作记忆与长期连续性。

**P3：下一轮细节与规模验证**

- 搜索输入和上一处/下一处箭头补可访问名称：web/src/views/SessionView.vue:1094。为异步错误与结果提供一致的读屏反馈。
- 为持续的连接动画和旋转加载动画提供减少动态效果的适配：web/src/styles.css:282、web/src/styles.css:549。已有按钮焦点样式应保留。
- 项目搜索、会话筛选和展开状态可写入 URL 或合适的状态存储，避免返回页面后重新整理：web/src/views/ProjectsView.vue:21。
- 仓库和会话达到 50/200 项时再做真实渲染性能测试，决定是否需要分页、虚拟列表或按设备分组。本轮不将未测量的性能问题当成已确认缺陷。
- 登录页视觉较克制。新增设备引导、注册不可用时的下一步和产品价值说明，比增加装饰更有帮助；不要泄露邮箱存在性或用户数量。
- 审计日志可补新动作的人类可读名称，例如本次新增的 device.update.check / device.update.restart：web/src/views/SettingsView.vue:107。

**建议实施顺序**

第一轮：草稿保护、后台续跑失败可见、文件列表错误/空状态分离、项目页恢复原对话。这些改动直接减少工作损失和功能断点。

第二轮：统一项目/会话/原对话/工作区概念和入口；补升级阻塞原因、检查时间与安排状态；改善业务错误和键盘模态行为。

第三轮：项目工作摘要、终端移动端操作分组、规模化列表与视觉细节。保持现有卡片、配色和终端的视觉语言。

建议用五个真实任务验收：从项目继续一个已结束对话；输入长提示词后查看 Git 再返回；首次断网读取后台任务；安排升级后找出阻塞项；从运行结果走到文件审查、提交、推送和人工验收。记录是否能完成、是否需要帮助、是否走错入口和是否丢掉已输入内容，不凭主观分数宣布体验通过。

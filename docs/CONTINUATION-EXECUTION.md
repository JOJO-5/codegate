# 预约与续跑：历史整理和执行观察

2026-10-18 实现说明。Server、Agent 与 Web 需一起更新；尚未部署到本机活动 Agent 或线上服务。

## 用户流程

- 设备页先显示目标设备，再显示“预约与续跑”。按进行中、需要处理、历史记录分类，避免旧记录挤占当前工作。
- 未运行的任务可“取消预约”；运行中可“停止本次执行”，等待 Agent 确认后才结束。撞墙监测的入口为“关闭自动续跑”。
- 已完成、失败、已取消记录支持“删除记录”和“清理当前列表历史”，可撤销。刷新、重新登录不恢复已删除记录。删除是服务端持久软删除，原记录保留以支持撤销与执行幂等，不是物理擦除；不删除项目文件、原生历史或本机回执。
- 需要确认的任务保持在“需要处理”，不能直接删除。取消安排后可以整理历史，但原执行结果是否已确认仍以详情为准。
- “查看执行”显示本次尝试、原生对话、原会话链接、启动时间、运行时长、最近同步和可用活动。预约运行使用只读执行记录；链接打开原会话记录，不会自动重发任务或启动另一个执行。
- 执行结束显示结束时间和最终回复，不再显示下次派发时间。进程退出仍需用户核对实际任务结果。

## 数据与恢复

任务协议新增可选 `progress`：尝试内递增序号、启动/同步/活动时间、安全活动标签、最近模型文字。CLI 进程每两秒发送快照；Web 在执行时每三秒读取，其他时候十五秒读取。这里只保留有界的最近快照，不提供完整的逐事件日志回放。

Codex 结构化工具事件显示命令、文件和工具的活动种类，不上传原始命令参数、工具输出或 stderr。OpenCode V2 显示已确认的原生回合活动及模型文字；详细工具事件暂不可用。其他 CLI 仅显示适配器实际能解析的回复与进程状态。旧 Agent 没有 `progress` 时，界面明确说明能力不足。

Server 校验账号、设备、尝试和活动序号；旧尝试及旧快照不能覆盖新数据。重试进入下一次尝试时清空旧快照。Agent 保存最近快照，最终状态在进度协程结束后发布。读取失败保留最近数据；超过十五秒未同步时标记更新延迟，不推断为进程停止，不重放模型请求。

删除和撤销按任务所有权校验，并与取消、派发、回执更新共享任务锁。仅允许结束记录删除，保留原 nonce，迟到创建请求不会启动第二次执行；前端使删除/取消之前的在途列表失效。批量清理逐条提交，失败保留已完成数量，可撤销已删除部分。当前列表上限仍是200，达到上限会提示；分页尚未实现。

## 设计心理学

入口按用户目标命名，分清安排、执行和历史；提供真实活动与停止回执，降低等待的不确定感；历史整理支持撤销，删除后焦点移到撤销入口，撤销后返回历史分类。高级原生身份在详情内展示，主列表保持简洁。

## 验证与边界

- Go 回归覆盖跨账号拒绝、活动任务禁止删除、持久隐藏与撤销、nonce 保留、旧快照过滤，以及主脑认证阻塞后停止继续派发。
- Windows 实际拥有的测试进程在退出前发布模型文字，取消后保留活动与输出；不调用付费模型。
- 前端 SFC 与渲染测试覆盖删除/取消旧响应、离线数据保留、需要处理入口和真实空状态。
- Playwright 在隔离模拟服务验证实际页面的单条删除、键盘撤销、批量清理、刷新保持、执行详情、停止待确认、读取失败保留数据；390×844 下内容宽390，无横向溢出。该检查不等于生产账号及实际模型验收。
- 初次 OpenCode 实测被凭据过期401阻塞；同日本机更新认证后，Big Pickle 免费模型的实际调用、取消和完整主脑/工作模型交付链均通过，测试会话费用为零。未静默转付费模型或放宽工具约束；其他模型及线上环境仍需分别验收。读屏器人工验收未执行。

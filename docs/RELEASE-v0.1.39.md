# v0.1.39

修复 Codex 原终端仍运行、自动续跑却无法连接控制服务的问题。普通 Codex 终端启动前确认共享服务可用，必要时通过本机已授权 CLI 幂等启动，并明确连接同一个服务；不重启用户已有服务，不静默回退到无法监测的独立进程。

开启自动续跑前，服务端要求 Agent 只读核对原会话身份、加载状态和工作目录。检查失败不会创建任务，界面保留输入并显示恢复步骤；等待时防止重复点击，切换会话后的旧响应不会关闭新对话框。并发提交保持 nonce 和原生对话防重，检查等待不阻塞其他任务取消。

设计心理学：区分“终端运行”“正在核对”“已经监测”；失败保留输入和控制权，并明确说明尚未开启及下一步操作。

需要 Server 与 Agent 共同更新。旧 Agent 会收到明确升级提示；运行中的 Agent 保留空闲更新。旧独立进程不能无缝接管，更新后需在合适时机结束原终端、恢复原对话一次。显式独立进程或自定义控制地址仍可作为普通终端使用，但不支持本次共享服务续跑。

验证：Go Agent、Server、Protocol 测试，前端回归、类型检查和生产构建，以及 Linux amd64 编译通过。真实 Codex 0.163.0 隔离验证后台服务冷启动、复用、完整 Agent 创建终端和终端关闭后的服务存活；模型调用为 0。浏览器隔离验收 15 项通过，包括 320/390/1440 像素布局、键盘、等待/失败/恢复和刷新恢复。

无新增数据库迁移。真实订阅额度耗尽、恢复并驱动模型继续的完整生产流程仍待验收。详见[故障证据与修复说明](FIX-CODEX-LIVE-CONTINUATION-2026-10-23.md)。

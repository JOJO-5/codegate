# 接回终端近期报错排查

2026-11-13，北京时间。用户确认遇到“会话不存在/已关闭”和“设备离线/连接超时”。本次只做本地修复与隔离验证，保留此前尚未提交的 v0.1.49 优化；线上 Server 与本机受管 Agent 仍为 v0.1.48。

## 现场证据

- 线上容器健康，最近 48 小时抽查未见 HTTP 5xx；98 条慢请求中 96 条来自 WebSocket 长连接的存活时长，不能把这些日志都视作接口故障。
- 本机 Agent 日志确有上游连接被关闭、握手/读超时及随后重新认证的记录。只有一条正常启动链：background launcher → supervise → v0.1.48 run，未发现两个 Agent 互踢。
- 11 月 12 日 23:56～23:59 及 13 日 07:28 的 `session.detach / session_not_found` 均发生在对应终端关闭之后。这些是检查恢复链的线索，不能单凭一条日志断言每次前端报错都来自此处。

## 已复现并修复

### 关闭后的旧连接标记残留

Server 的 `ForgetSession` 只清除订阅与终端视图，没有清除 ClientConn 的 attached/attachID。Agent 在关闭、回收或重启后返回 `session_not_found` 时，Server 也没有完成解除订阅。前端虽容忍这一错误，Server 仍可能以 `already_attached` 拒绝下一次接回，形成需要刷新浏览器才能脱离的状态。

修复：会话结束同时释放其浏览器标记；经鉴权且与原 Agent 匹配的 detach 回执若明确表示会话不存在，按幂等解除连接完成清理。离线、超时、结果不明和无权访问仍保留错误，不能伪装成成功。新版 Agent 对已回收会话的 detach 直接确认完成，避免正常收尾产生失败告警；Server 兼容旧 Agent。

### 浏览器连接正常时，电脑 Agent 的掉线未被界面感知

浏览器和电脑 Agent 分别连接 Server。原终端页面主要监听浏览器自身断线；已经接回后，仅电脑链路断开不会及时使终端进入等待状态，也没有在电脑回来后明确触发一次重新接回。网络断线本身仍可能发生，这次修复的是应用的状态与恢复缺口。

修复：新增仅 Server 可发送的 `session.connection` 通知，限定该设备所有者的终端视图接收。掉线时终端停止接受输入，显示正在等待电脑；重新认证后必须完成会话对账才通知 ready，并接回原终端。旧 Agent 连接的迟到清理不能覆盖新连接。浏览器自身重连仍走原 attach 流程。

只重接现有终端，不自动执行 `session.create` 或 `conversation.restore`。原进程在 Agent 重启后确实不存在时，进入已结束状态，让用户显式恢复原生历史。未发送草稿保留；用户选择停止自动接回后，电脑上线不会撤销这一选择。迟到的 attach 回执也不能覆盖已收到的离线状态。

## 设计心理学落实

区分“浏览器已连接 Server”“电脑 Agent 在线”“终端进程仍存在”和“恢复原生对话”。等待使用状态提示，展示明确的停止自动接回、手动重试和恢复入口，不用虚假的成功回执。手机黑色终端上的浅色提示提高对比度，去掉重复的掉线错误条。

## 后续检查：取消与恢复回执边界

继续检查接回与原对话恢复，另外复现并修复三处问题：

1. **停止后仍可能继续重试**：停止原来只取消已排队的计时器，无法阻止在途请求稍后的失败重新排队，也无法阻止迟到成功重新启用输入。现在停止会使本轮接回失效，清除排队的重放，所有自动接回入口均尊重停止选择；请求及重放等待期间也提供文字按钮。手动重试仍然可用，不结束远端进程，草稿保留。
2. **重试失败抹掉第一次的未知结果**：第一次恢复丢失回执后，即使用户明确确认重试，第二次的设备离线也无法证明第一次未执行。现在保留原待核对状态和跨刷新标记，继续通过实时结果检查恢复入口，普通重试不能绕过核对。
3. **跳转失败误判为恢复失败**：原实现收到恢复结果后，先清除待核对标记并关闭面板，再跳转终端。现在在跳转完成后清理标记；跳转抛错或被中止时明确提示对话已恢复、页面未打开，保留检查入口，禁止直接再次启动。目的终端已经打开的重复导航按完成处理。

设计心理学：停止接回与结束进程区分；恢复完成与页面打开区分；未知结果保留可核对记录，避免失败文案诱导重复执行。关键等待阶段可以用键盘操作停止按钮。

验证：新增回归在修改前分别以“迟到失败重新排队”“重试错误清除未知结果”“跳转失败后允许重复恢复”失败，修改后通过。覆盖迟到成功、自动重放门控、手动重试、草稿保留，以及跳转失败后只读检查、导航中止和重复导航。`test:conversations`、`test:ux` 与类型检查/生产构建通过。隔离浏览器使用真实 Vue 构建和模拟 HTTP/WS，验证在途停止、迟到失败/成功、键盘 Enter 停止、手动接回及草稿保留，创建进程计数为零、页面运行时异常为零；390px 和 1440px 均无横向溢出，390px 截图已查看。

本轮只修改前端与测试/说明，恢复派发和导航异常通过组件回归验证，未进行真实模型、真实远端进程或线上验收。没有提交、推送或部署。

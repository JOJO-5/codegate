# 连接等待与会话恢复排查

2026-10-30。排查基线为线上 Server 与本机受管 Agent v0.1.46。本次修复纳入 v0.1.47 发布；以下验证为发布前本地验收，线上部署与 Agent 激活以实际回执为准。

## 证据和原因

- Agent 日志显示：成功认证后，下一次断线的重试次数仍累计到 200 多次，等待约 20～45 秒。实际运行循环没有调用已有的 backoff.Reset，原先只测试了 Reset 方法本身。
- 同一时段存在 TCP/TLS/WebSocket 链路的握手超时、读超时和连接被远端关闭，涉及 IPv4 与 IPv6。没有证据证明单纯禁用 IPv6、重启 Agent 或刷新浏览器能修复外部链路。
- Server 在 Agent 断线时静默清除待回请求；TTL 到期时发送的错误还缺少 reply_to。浏览器无法及时确认哪条请求失去回执，恢复入口最终显示泛化的超时重试。
- 浏览器连接和 Agent 连接互相独立。浏览器仍连着 Server 时，Agent 掉线导致的接回失败不会触发浏览器重连事件，终端可能一直停在错误状态。
- 用户此次恢复报错的具体文字与发生时刻尚未取得，不能把所有恢复失败归于同一个原因。没有停止或接入正在运行的用户终端来制造复现。

## 修复及设计心理学

认证成功才清零 Agent 退避；失败的拨号和认证继续退避，保留限流与防重试风暴机制。Server 对失去回执的请求返回带原 request ID 的“结果尚未确认”，不宣称操作一定失败，也不标成可自动重放。

“接回已有终端”和“恢复原生对话”使用不同的恢复策略：

- 接回只重新订阅既有终端，针对离线、超时及回执不明最多自动重试六次，保留输入。等待时有明确说明和“停止自动重连”；断线、离开页面、进程退出时取消旧计时器，旧结果不能覆盖新状态；耗尽后可手动重试。
- 恢复原生对话最多等待 55 秒回执，配合 Server 的 60 秒请求 TTL。断线或超时进入结果待确认，保留原生身份与本标签页的恢复意图。关闭重开、刷新都先核对，不能直接再发恢复请求。
- “检查恢复结果”要求 Agent 的实时会话，不能把缓存当成功。只有设备、原目录、工具和原生身份匹配且结果唯一时才进入终端。实时核对没有发现终端后，可明确二次确认再恢复同一原生身份；不自动重放。多个候选要求返回列表核对。
- 浏览器存储不可用时说明待确认标记无法跨刷新保留。凭据和对话内容不进入该标记；账号切换失效旧响应。

这些行为用真实状态和可执行下一步代替“超时就重试”，保持用户对任务和历史的控制。

## 验证与限制

- 新增真实本地 WebSocket 认证/断线循环测试：修复前第二次故障计数为 2，修复后每次已认证连接的下一次故障均从 1 开始。
- Server 回归先复现断线无回执及 TTL 错误缺失 reply_to，再验证对应请求的结果不明、非自动重试语义、幂等清理及其他设备隔离。
- Vue 回归覆盖自动接回次数上限、手动重试、页面离开取消、输入保留、结果核对不重放、关闭/刷新保留意图、实时核对及明确确认后的同身份重试；原有旧响应/会话切换测试保留。
- Agent、Server、Protocol 测试及 Go 命令构建通过；前端会话、UX 回归及类型/生产构建通过。隔离浏览器 19 项检查通过，包含 320/390px、刷新/重开不重放、缓存不当成功、身份核对、停止/手动/自动重连、确认前不派发及确认后只派发一次；使用模拟 HTTP/WebSocket，不调用真实模型。
- 发布前未验证长期真实公网掉线率、真实手机触摸/软键盘或真实模型恢复。修复的是程序放大的等待和错误恢复路径，不代表公网网络故障已经消失。

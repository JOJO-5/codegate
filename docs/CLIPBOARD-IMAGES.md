# 会话图片粘贴

版本：v0.1.38。复用现有工作区附件上传协议，Server 与 Agent 无改动。生产部署状态以发布验收回执为准。

用户可在终端、终端文字输入框或附件区按 Ctrl+V / ⌘V 粘贴图片，也可打开“附件 → 粘贴图片”。图片进入本地待上传列表，保留已有文字；用户确认上传后，继续使用“路径加入输入”或 OpenCode 原生附件入口，并自行确认发送。普通文字继续由原输入框或 xterm 处理。

设计心理学：图片粘贴后立即显示预览和“待上传”，明确区分添加、上传和发送；读取失败提供快捷键和选择文件入口。未上传图片刷新/离开会话会清除，界面直接说明；收起附件会取消尚未完成的读取，已有选中图片保留。离线/失去控制权阻止新添加；重连后可重试。最多保留 20 项、单文件 100 MB，沿用既有边界与上传取消机制。

实现注意：用捕获阶段处理图片粘贴，避免混合图片/文字被同时发往终端。Ctrl+V / ⌘V 交给浏览器产生 paste 事件，不让 xterm 编码为 Ctrl+V 控制字节。不会读取剪贴板 HTML 或下载其中的远程图片。按钮读取仅在用户点击时调用 Clipboard API；兼容性及权限行为参见 [MDN Clipboard.read](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/read)。

验证：

- `npm --prefix web run test:transfer`：真实辅助模块与附件组件逻辑，覆盖图片去重、文字放行、仅预览、失败重试、权限拒绝/空剪贴板、超限、离线恢复、收起/卸载/断线后迟到读取的丢弃，以及控制权门控。
- `npm --prefix web run test:ux` 与类型检查/生产构建通过。
- 隔离 Chrome 浏览器 15 项检查通过：系统剪贴板写入测试图片后，在真实 xterm 与文字输入框按 Ctrl+V；按钮读取；上传失败重试与路径加入输入；不自动上传或发送；模拟权限拒绝后使用 paste 事件恢复；320/390px 布局和键盘聚焦；普通文字粘贴；无 pageerror。文件传输由隔离 WebSocket 服务应答，未连接真实 Agent 或调用模型。

尚未验收：Mac 的实际 ⌘V、Safari/Firefox、手机系统剪贴板与软键盘，以及真实模型的图片理解。图片能否被识别依赖 CLI 与所选模型能力。

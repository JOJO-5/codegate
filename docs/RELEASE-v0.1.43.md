# v0.1.43：Codex 会话启动与恢复可靠性修复

本次修复 Codex 控制服务无法在 Windows 后台启动器中独立运行的问题，补充真实失败原因和恢复提示，并修正代理流中断处理。没有数据库迁移。排查证据见 [会话故障记录](SESSION-INCIDENT-2026-10-25.md)。

## 改动与使用

- Windows 后台启动器允许 Codex 显式申请独立驻留；普通 Agent 与终端子进程仍由宿主管理，结束宿主时正常清理。已有控制服务时不重启或替换共享服务。
- 新建、恢复失败时区分后台启动器限制、程序缺失、权限、超时和服务尚不可连接。提示保留原会话并给出下一步，不将启动命令退出当作连接成功，不返回原始 CLI 输出或凭据。
- HTTP 代理遇到 `http.ErrAbortHandler` 时正确中断不完整响应，避免截断内容被误判为正常完成，同时不再误报 handler panic；真实程序异常仍记录并返回 500。
- DSH 默认沿用其原生界面。运维可通过 `CODEGATE_DSH_MOBILE_UI=true` 显式启用原兼容层，`false` 关闭，不修改 DSH 安装文件。

## 更新边界

Server 发布后，Agent 可先下载新版并等待空闲切换，不为更新强制关闭正在运行的会话。Agent 二进制更新和 Windows 后台启动器更新是两件事：旧启动器需使用本版本配套的 `agent-autostart.ps1` 与 `agent-background-launcher.cs`，在会话空闲后执行 `repair`；该操作可能要求 Windows 账户验证。发布包附带这两个文件，Server 安装脚本下载入口也提供同版来源。本机启动器已核实包含修正，不需要重复修复或重启。

## 设计与验证

保留原入口和会话，失败说明原因与恢复动作；区分服务启动、连接成功和用户任务完成，避免盲目重放。默认使用 DSH 自有布局，减少额外界面干预。

- Agent、Server、Config 包测试与 vet 通过，错误分类和 HTTP 截断响应已先观察失败再修复；覆盖诊断上限、敏感输出隔离、真实 panic、正常/截断流与配置开关。
- Windows 实际 Codex 0.164.0 隔离对照：旧启动器返回系统错误 5，新启动器成功；普通子进程清理、显式独立进程存活、无窗口和退出码验证通过。
- 真实 CLI 隔离启动、保存历史、关闭终端、缺失历史失败、恢复原对话、重复恢复复用均通过，模型调用为 0。

上述验证不等于线上用户任务或浏览器等待后重试已经稳定。没有调用真实模型，也没有完成手机实机与读屏验收。实际部署、产物校验及 Agent 切换状态以发布记录为准。

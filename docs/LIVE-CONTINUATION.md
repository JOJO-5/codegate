# 原终端自动续跑（v0.1.29）

正在执行的 Codex、Claude Code、OpenCode、DSH 对话可在终端顶部点击「自动续跑」，或从设备记录的「安排继续」选择「撞额度墙后在原终端自动继续」。这是当前回合的显式授权，不会默认对所有对话启用。对话需要已经绑定原生身份。

保存后立即监测当前回合；网页关闭仍有效。确认原生回合失败后按错误类别等待，并把继续指令送给同一原生对话。正常完成、中断、新回合、手动按键/输入或关闭原终端会关闭自动控制。不会关闭原终端来启动另一个后台 CLI。取消、需要审批、登录/权限、参数、上下文窗口和无法识别的错误不会被当作临时网络故障重试。

## 不同 CLI 的接入

| CLI | 失败与回合状态 | 继续方式 | 兼容要求 |
| --- | --- | --- | --- |
| Codex | 本机 app-server 的 `thread/read`、`thread/turns/list`、结构化 `codexErrorInfo` | 同一守护进程 `turn/start`，保留模型、目录与审批策略 | 需默认本机守护进程和这些接口；不启动替代守护进程，不适用于 `--no-daemon` 或外部 remote 服务 |
| Claude Code | 原生 `UserPromptSubmit` / `StopFailure` / `Stop` 钩子 | 原终端提交继续文字，必须收到匹配文字摘要的原生提交回执 | 为避免破坏旧版启动，只对检测到 >=2.1.296 的 CLI 加钩子；保留原 `--settings` 和已有钩子 |
| OpenCode | 插件的原生消息/会话错误事件，加原生状态/历史查询兼容新事件版本 | 插件 SDK 在同一 session 调用 `promptAsync`；使用原模型/agent，消息 ID 由 OpenCode 生成 | 使用新启动/恢复的事件桥终端；支持所需 SDK 方法 |
| DSH | 原生 `turn/start` / `turn/end` 与 `LlmFailure` 的 code/status/delay | 同一现有 Agent 的 `followup` | 使用新启动/恢复的事件桥终端，需 Agents/turn 事件接口 |

Claude/OpenCode/DSH 的旧进程不能补装生命周期钩子/插件；更新 Agent 后恢复原对话启动一次新终端即可保留原生历史。未提供可靠状态或接口不兼容时会显示失败原因，不能假称已经开启。仅有历史文字的终端不做屏幕关键词扫描。

## 等待与次数

默认最大自动重试3次，可设1–10次。额度模式和可选的临时故障重试共同计入此上限；等待检查不计为重试。临时故障采用10秒、30秒、2分钟、5分钟的退避，服从原生返回的更长重试时间。登录/账单/参数/审批等错误不循环重试。

Codex 额度恢复必须由本机接口明确返回 `ordinaryUsageAllowed: true`；百分比变低、重置时间已到或查询失败都不足以触发提交。不会调用重置额度、购买 credits 或更换账号/模型的接口。

Claude 的默认订阅配置、OpenCode 的原生 `opencode-go` 路由可查询对应本机订阅额度。自定义 API/其他模型不能拿不相关的订阅额度来判断。没有查询接口时，优先使用错误返回的重试/重置时间；否则按用户设定的额度等待时间（默认300分钟，1–10080分钟）做有限尝试。这是定时再试，不表示已确认额度恢复。继续使用用户原 CLI/provider 的账单和审批策略。

Server 保存设置并约每30秒向 Agent 检查当前回合；网页列表每15秒刷新。额度拒绝/查询失败会至少缓存一分钟，减少持续查询。第一次派发通常在5秒内。时间不是硬实时保证。

自动开始的回合有本机5秒检查的运行上限守护，不依赖网页或 Server 保持连接。默认本次上限120分钟，1–360分钟；取消/超时时仅请求停止本任务开始的原生回合，保留终端。原生控制接口失联而无法确认停止时，进入「需要确认」，不会猜测结果或强杀共享守护进程。电脑和 Agent 需保持运行；Agent/原终端退出时停止自动控制。

## 回执与并发

每个自动提交先保存本机准备回执；插件也在 native 提交前保存准备确认。丢失回应、崩溃或不能证明提交结果时进入「需要确认」，不会再次发送同一指令。手动输入优先，新原生回合会让监测让出控制；每个原生对话只允许一个未结束的自动监测任务。

跨应用原生服务未提供通用的原子“检查旧回合并提交”接口，极短的外部客户端竞态仍由原生 CLI 的输入/回合调度处理；本功能不承诺模型和外部工具副作用恰好执行一次。继续指令默认要求检查已完成工作，避免重复操作。

本机事件记录仅保存身份、状态、错误类别及文字摘要哈希；不保存钩子的完整回复、错误详情或凭证。继续指令仍按任务设置保存在 Server/本机控制请求中，原生历史由 CLI 维护。

## 验证范围

- Agent/Server 回归和 race：可靠额度许可、临时错误退避、次数上限、原生 `systemError`、同一原生 ID、重复任务、丢失确认、手动新回合优先、原生取消、离线 Server 时的本机运行上限。
- 实际 Codex 本机守护进程：本地模拟服务返回额度错误，读取结构化失败，再在同一 native thread 继续完成，无进程重启。
- 实际 Claude Code 2.1.296 TUI：本地模拟额度错误触发 StopFailure，原进程接受继续文字并产生新的原生提交及完成回执。
- 实际 OpenCode 1.18.33：本地模拟服务产生会话错误，插件保留原模型，在同一 session 继续并完成；兼容新版本的 session.next 完成事件。
- DSH 原生接口按公开 Agent/Session 合约运行插件适配测试，验证 followup、同一身份、字面指令和重复控制请求保护；实际 DSH TUI 也已使用本地模拟服务验证结构化额度错误、同一 Agent 的 followup 和完成。未使用真实付费订阅额度墙，不能声称已经验证所有厂商的真实重置行为。

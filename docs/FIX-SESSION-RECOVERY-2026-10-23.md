# 会话页内恢复原对话与关闭后的切换修复

## 用户目标与入口

用户在会话工作区选择已经结束的终端后，仍能查看所属设备、项目目录和其他会话，并可在当前页点击“恢复原对话”。恢复会重新启动获本机授权的 CLI、加载已保存的原生历史；不会自动发送任务或模型消息。普通 Shell 明确说明不支持原生对话恢复。

## 原因与修复

- 原终端页只在 attach 成功后填入会话摘要。关闭的 PTY 无法 attach，摘要为空导致设备 ID 和侧栏列表一起丢失。新增受现有会话权限检查保护的 `GET /api/v1/sessions/{session}`，并从已有列表立即保留上下文；冷刷新通过缓存元数据建立上下文，活跃终端仍以 Agent 的 attach 回执确认。
- 连接队列把已经消失的终端的 detach 错误当作切换失败，旧终端引用因而无法清除。仅对 `session_not_found` 视为已无须 detach；离线、超时和其他错误仍保留真实失败及重试路径。
- 已结束的会话不再反复接回失效 PTY，直接显示结束状态、恢复入口和切换入口。滞后的运行状态若在 attach 时确认不存在，则转入结束状态。断线重连只接回存活进程，不自动恢复另一进程。
- 复用现有 `ConversationRecovery` 与服务端可信来源、Agent 白名单及恢复防重逻辑。读取历史失败可重试；恢复失败保留已读取列表和选择。恢复提交防重复，旧来源或已卸载组件的回包不能关闭新弹窗或触发旧会话导航。收到成功回执后导航，不等待另一次会话列表读取完成。
- 元数据和 attach 的延迟响应不能覆盖已收到的进程退出/关闭状态。

## 设计心理学

明确区分终端进程、原生对话历史和恢复操作：结束状态不会伪装成连接失败，按钮说明恢复目标；等待显示当前阶段，失败说明尚未确认成功并保留选择。退出状态保留切换控制权；离线操作说明禁用原因。手机侧栏提供文字入口、展开状态、焦点转移和 Escape 返回。

- 修复前运行回归，证实关闭记录无法提供上下文、缺少独立元数据接口、已消失终端 detach 阻塞切换；实现后对应回归通过。
- 真实 SQLite/HTTP 测试覆盖关闭且设备离线时读取摘要、保留原生绑定、未登录拒绝、跨账号与不存在记录返回一致的错误。
- 前端实际组件/连接 Store 回归覆盖关闭上下文、冷刷新、滞后状态、切换、重复恢复、旧来源回包、恢复失败，以及元数据/attach 延迟响应不能复活已关闭终端。
- `npm run test:conversations`、`npm run test:ux`、类型检查、生产构建通过；`go test ./internal/server ./internal/protocol` 通过。
- 本机构建配合隔离 HTTP/WebSocket 边界，真实浏览器 26 项检查通过：失败后切换、旧 PTY 消失、断线重连、元数据/历史读取失败重试、恢复失败保留选项、成功恢复导航、刷新不重复恢复、320/390/1440 布局、手机侧栏和键盘焦点。另人工查看 320px 结束页和失败弹窗截图；无浏览器运行时错误，终端输入计数为 0。

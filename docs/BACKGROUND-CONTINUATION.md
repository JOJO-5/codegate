# 原生对话后台续跑（v0.1.25）

在设备的 Codex、Claude Code、OpenCode 记录或终端顶部点击「安排继续」。选择现在安排或指定最早时间，填写继续指令和运行上限。到期时，若同一原生对话已在本机打开，等当前回合空闲后在该对话提交。若已关闭，Agent 在后台恢复同一原生历史并执行。Server 保存预约，网页可以关闭，设备离线时等 Agent 重新上线。新预约需要支持此功能的 Agent。旧预约使用已保存的执行方式。

「按时间继续」使用原对话的 CLI 和模型配置。「等订阅额度恢复后继续」只用于能可靠查询对应额度的配置。多个窗口都耗尽时，以最晚的恢复时间为准，到时再核对。查询失败时提示核对本机登录或改用按时间继续。新预约提交一次，执行结果不明时进入「需要确认」。

执行使用 Codex `exec resume`、Claude `--print --resume`、OpenCode `run --session`，指令只送 stdin，不拼入 shell 命令。Agent 在启动前核对授权目录、CLI、本机原生历史和是否已有终端/后台任务占用同一对话。不会新建对话代替缺失的历史。CLI 的本机审批策略继续生效，后台执行遇到交互审批可能失败，应回原对话处理。

每次执行有独立身份和本机原子回执；准备标记在进程启动前落盘。Server 重启后查询回执，不重新发送指令。响应丢失时先等待重连核对回执；若 Agent 崩溃留下无法确认的准备/运行回执，则进入「需要确认」；用户核对原生历史后可以重新安排。无法承诺模型或外部工具副作用恰好执行一次。

排队阶段可以直接取消；运行阶段取消会停止本次提交的原生回合或 Agent 启动的后台 CLI。默认本次上限120分钟，可设1–360分钟。取消和超时保留已经完成的文件和对话。后台任务运行期间，打开同一原生对话需等本次执行结束。

Server 每5秒检查到期任务；等待离线设备每60秒复查；运行回执每30秒核对。网页任务列表每15秒刷新。额度面板在可见且网页前台时每30秒自动刷新，Agent额度缓存15秒，网页请求15秒超时。时间不是硬实时保证，查询、网络和启动开销会增加等待。

保存指令和最终模型文本摘要（上限16KiB），不保存 CLI stderr、工具执行日志或整个本机环境。任务通过设备所有权授权，浏览器不能直接发送 Server 的执行指令。每台设备最多20个未结束任务，提交 nonce 防止网络重试重复建任务。列表展示最近200条记录。

执行状态「本次执行结束」表示 CLI 已结束，用户仍需在原生对话核对结果。旧后台额度任务继续使用保存时的重试上限。

也可选择[撞额度墙后在原终端自动续跑](LIVE-CONTINUATION.md)，支持 Codex、Claude Code、OpenCode 和 DSH。这个选项监测当前回合，重试次数可在开启监测时设置。

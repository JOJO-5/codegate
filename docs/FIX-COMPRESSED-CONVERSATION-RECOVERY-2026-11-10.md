# 压缩历史恢复修复

2026-11-10，本机 Agent 多次拒绝 `conversation.restore`，返回“没有找到原生对话”，请求尚未启动恢复 CLI。只读核对确认，相关原生对话仍保存在 `.jsonl.zst` 文件中，文件头身份与服务端绑定一致；Codex SQLite 中的目录使用 Windows `\\?\` 扩展形式。

## 原因与修复

- 历史扫描和解压仅支持 `.jsonl` / `.jsonl.zstd`，漏掉 `.jsonl.zst`。增加该压缩后缀，沿用现有解压内存、扫描字节数和目录限制。
- 原生数据库中的扩展目录与普通工作区路径指向同一目录，但字符串比较不相等。Windows 下比较失败后核对文件系统身份；工作区授权入口、目录白名单和不同项目隔离保持原有校验。
- 本地版本更新为 v0.1.48；无需数据库迁移。需要运行新版 Agent 才能生效。

用户目标仍是从“恢复原对话”进入同一个已保存的原生对话。通过识别真实历史避免误报删除；等待、失败、回执不明及恢复防重沿用现有流程，不自动发送提示词或更换模型。

## 验证

- 先复现 `.jsonl.zst` 历史丢失和扩展目录匹配失败；修复后回归通过。覆盖普通/两种压缩后缀、指定身份、身份缺失、其他目录隔离和原有 SQLite 筛选。
- Agent 全包测试通过。隔离的 Codex CLI 0.164.0 完成保存历史、停止隔离守护进程、压缩历史并移除隔离原文件、冷启动恢复，以及原有关闭后恢复、历史缺失拒绝、重复恢复复用；模型调用为 0。
- 本机真实历史只读查找另由显式启用的 `TestCodexNativeHistoryReadOnlySmoke` 核对，不打印对话正文。
- 以上为发布前验证，未替换运行中的 Agent、恢复真实用户对话或部署线上服务。本次未修改界面，真实手机和线上恢复仍需运行新版 Agent 后验收；实际发布状态以发布记录为准。

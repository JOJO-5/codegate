# Terminal interaction and process cleanup (Agent v0.1.19)

Windows ConPTY sessions now create their launcher suspended, assign it to a private kill-on-close Job Object, and resume it. Closing a session or terminating it stops owned descendants, including a CLI worker that detached from the console or survived its launcher. Other processes are outside the job. Natural session completion also releases terminal resources. Unix terminals retain a private process group and clean it even when the launcher has already exited.

Unix PTY I/O keeps a stable nonblocking descriptor instead of calling os.File.Fd on each read/write/resize (which can restore blocking mode). Read/write readiness waits on poll plus a dedicated shutdown pipe, so an idle or blocked reader wakes immediately on close without a periodic sleep. The size probe registers its change listener before reporting startup readiness.

Phone touch scrolling is coalesced once per animation frame. Native TUI mouse protocols still come from xterm; their reports are concatenated in order into one stdin frame for that draw, preserving binary mouse encoding. Ordinary local scrollback has bounded inertia, cancelled by a new touch, opening text selection, or leaving the session. Alternate-screen TUIs receive no inertia; their history/navigation remains controlled by the CLI. Keyboard input is sent immediately and never buffered behind the scroll frame or echoed speculatively.

Local production Server + native Agent + Chromium mobile tests measured real keydown-to-PTY-echo at about 8 ms median / 12 ms p95 on loopback. This does not measure the user's internet path or claim a lower WAN round-trip time. Real touch tests verified local history with inertia and no stdin, 7 mouse reports carried in 4 frames, no mouse input after release, and multi-client read-only/takeover behavior. Native terminal regression tests verify child socket release for both a live and an already-exited launcher; Windows fixtures explicitly detach the child from ConPTY.

## Weak network scheduling and measurement (v0.1.20)

Server and Agent WebSocket writers maintain two bounded FIFO lanes. Terminal states, replay, live bytes, input, and session controls share the interactive lane. All file and Web tunnel lifecycle controls and data share the bulk lane, so opening/closing a stream cannot overtake its bytes. Interactive messages go first; one ready bulk message is served after eight interactive messages to prevent starvation. The additional bulk queue is capped at 16 messages. Existing enqueue overload/error and terminal replay policies remain in effect; this is not an unlimited buffer or a guarantee against overloaded connections.

Browser uploads and file reads start with 32 KiB chunks. An acknowledgement above 600 ms halves the next chunk down to 8 KiB; below 120 ms doubles it up to 64 KiB. Offsets, atomic upload commit, cancellation, and the existing 192 KiB protocol maximum stay compatible. This limits head-of-line blocking at the cost of bulk throughput on high-RTT paths. An active WebSocket frame or bytes already in the TCP/OS buffer cannot be preempted. This change does not coalesce keyboard input, invent CLI echoes, or reduce physical network RTT. Existing negotiated compression remains enabled.

Expand session information and select “测连接” for three request samples. Browser ↔ relay is an application request round trip; relay ↔ Agent includes relay queueing, transport and Agent processing; the complete request includes both legs. Results use the median and are not key-to-screen echo timings. Queue samples show the latest interactive wait and its age; they contain counts/timings only. Probes use session ownership checks and never write PTY input. Replies are consumed only from the expected device and user. Old Agents can answer a plain Pong and still provide the relay-measured round trip without Agent queue statistics; old Servers produce an explicit update message in the UI.

Regression tests cover lane FIFO, lifecycle ordering, bulk fairness, cancellation/heartbeat, slow-writer key priority, full bulk queues leaving room for controls, probe ownership and old-Agent compatibility. Browser transfer tests exercise fast/slow acknowledgements, byte integrity, offsets, progress and cancellation; these run in Web CI.

# Terminal interaction and process cleanup (Agent v0.1.19)

Windows ConPTY sessions now create their launcher suspended, assign it to a private kill-on-close Job Object, and resume it. Closing a session or terminating it stops owned descendants, including a CLI worker that detached from the console or survived its launcher. Other processes are outside the job. Natural session completion also releases terminal resources. Unix terminals retain a private process group and clean it even when the launcher has already exited.

Unix PTY I/O keeps a stable nonblocking descriptor instead of calling os.File.Fd on each read/write/resize (which can restore blocking mode). Read/write readiness waits on poll plus a dedicated shutdown pipe, so an idle or blocked reader wakes immediately on close without a periodic sleep. The size probe registers its change listener before reporting startup readiness.

Phone touch scrolling is coalesced once per animation frame. Native TUI mouse protocols still come from xterm; their reports are concatenated in order into one stdin frame for that draw, preserving binary mouse encoding. Ordinary local scrollback has bounded inertia, cancelled by a new touch, opening text selection, or leaving the session. Alternate-screen TUIs receive no inertia; their history/navigation remains controlled by the CLI. Keyboard input is sent immediately and never buffered behind the scroll frame or echoed speculatively.

Local production Server + native Agent + Chromium mobile tests measured real keydown-to-PTY-echo at about 8 ms median / 12 ms p95 on loopback. This does not measure the user's internet path or claim a lower WAN round-trip time. Real touch tests verified local history with inertia and no stdin, 7 mouse reports carried in 4 frames, no mouse input after release, and multi-client read-only/takeover behavior. Native terminal regression tests verify child socket release for both a live and an already-exited launcher; Windows fixtures explicitly detach the child from ConPTY.
